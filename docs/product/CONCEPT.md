1. Executive Summary
BRICX IQ is a complete, mobile-first and web-based Construction Command Center designed for the worldwide
construction market. It unifies site progress tracking, resource control, financial management, real-money transfers,
team collaboration, document management and strong role-based governance into one connected platform.

The platform is designed to operate across countries, currencies, languages, operating systems and device types while
preserving a consistent core experience. Project Owners retain ultimate control over users, projects, financial
transactions, documents, communication and system settings.

BRICX IQ supports local market requirements through automatic currency localization, exchange-rate handling, local
language presentation and region-aware configuration. Its architecture remains extensible so payment rails, regulations,
tax rules, date formats and other country-specific requirements can be added without changing the core platform.

The updated concept incorporates the original feature set, the previous gap analysis against leading construction
applications, and the following global requirements:

 • Worldwide market: the product is not limited to Africa and is intended for construction companies, contractors, owners,
   consultants and stakeholders globally.

 • Automatic currency localization: financial values are displayed in the project's/country's configured currency, with
   conversion and exchange-rate records where multiple currencies are involved.

 • Universal cross-platform access: web, desktop-class browsers, mobile phones, tablets and other supported devices
   across major operating systems.

 • Location-aware language: interface language can be selected automatically from location/device settings and can
   always be changed manually by the user.


2. Core Concept
The application functions as a Construction Command Center covering the full project lifecycle from pre-construction
through construction to handover. Physical progress, labour and materials, money in and out, team discussions and
project documents live in one connected system under the ultimate authority of the Project Owner.

The platform must be globally deployable while remaining locally adaptable. A project in Sierra Leone, the United
States, the United Kingdom, Ghana, Nigeria, Kenya, the UAE or another market should use the same core product while
receiving appropriate currency, language, regional settings and integrations.

7. BIM Integration & IFC Viewer Strategy
BIM remains a high-value but secondary module. The application should work excellently with 2D drawings first, with
BIM capabilities added progressively.

 • Phase 1: Robust 2D drawing management + markups; basic IFC model upload/viewing; create Issue or Punch item from
   a model location.

 • Phase 2: Object properties, measurements, section planes, selected-level offline caching, and linking model elements to
   tasks/RFIs/daily logs/cost codes.

 • Phase 3+: Federated models, version comparison, basic quantity extraction and optional premium cloud BIM path.

 • Recommended self-hosted/open approach: xeokit SDK or That Open + xeokit hybrid, with optimized IFC formats and
   offline caching.


8. Global Localization Architecture
Localization is a first-class platform capability rather than a later cosmetic feature.

 • Country profile: country/region, default currency, supported languages, date/time conventions and enabled payment
   providers.

 • User profile: preferred language, preferred currency/display settings and timezone.

 • Project profile: project country, reporting currency, project language(s), timezone and regional settings.

 • Transaction model: original amount + original currency + exchange rate + reporting amount + timestamp/source of rate.

 • Translation model: centralized translation resources with fallback language and user/project override.

 • Formatting: locale-aware dates, numbers, currency symbols, decimal separators and units.

 • Integration layer: country-specific payment, banking, tax, accounting and regulatory connectors can be enabled without
   changing core workflows.


9. Cross-Platform & Device Strategy
BRICX IQ must provide a consistent experience regardless of where the user accesses it. The platform should use a
shared backend/API and common data model while providing interfaces optimized for each device class.

 • Desktop/laptop: full project administration, financial control, reporting, document management and portfolio dashboards.

 • Tablet: field supervision, drawings, inspections, daily logs and project management.

 • Mobile: quick site updates, photos, attendance, approvals, messages, receipts and offline capture.

 • Web: responsive access from supported desktop and mobile browsers.

 • Android/iOS: field-focused mobile applications.

 • Windows/macOS/Linux: web/PWA or appropriate desktop delivery where required.

 • All clients use the same authentication, permissions, synchronization rules and source-of-truth backend.


10. Integrated Example Workflow
A typical global material purchase and site update flow demonstrates the connected nature of the platform:

 • Procurement raises a material request linked to a work package and cost code.

 • Request is approved according to role-based rules or escalated to the Project Owner.
 • Payment is initiated using an enabled local payment rail or bank transfer.

 • Transaction is recorded in the original currency and converted into the project's reporting currency using the configured
   exchange rate.

 • Confirmation and invoice are automatically attached to the expenditure record and document library.

 • Documents are shared in the Procurement or Finance chat channel and displayed using the user's/project's language
   settings.

 • Site team logs receipt with photos and updates the Daily Log; defects become Punch items.

 • If a design query arises, an RFI is created and linked to the drawing/model.

 • All activity appears in real time on dashboards and permanent transaction/audit history under Owner oversight.
